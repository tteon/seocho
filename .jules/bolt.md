- Learned: When streaming multi-GB `.jsonl` trace and evaluation workloads (common in the `scripts/` directory for benchmarking), `path.read_text().splitlines()` causes significant intermediate memory overhead by creating an entire list of strings before JSON parsing begins. Replacing this with `with path.open(...) as f: for line in f:` creates a lazy generator that parses records one-by-one, providing an immediate bounded memory optimization for all local data tooling without altering semantics.
